# Operate Amazon Crawler

Prefer the `crawler_*` MCP tools when the `amazon-crawler` MCP Server is connected. They provide typed inputs, structured outputs, tool annotations, and the same application service as the CLI. If those tools are unavailable, use `scripts/crawler_cli.py`; it fixes the project root, returns JSON, and blocks commands outside the safe operator surface. Do not switch between MCP and CLI during one operation unless the selected interface fails before creating a job.

## Runtime Ownership

For an ordinary local collection request, use MCP `crawler_run_job` or CLI `run`. It creates the durable root job, starts a scoped Worker in the same process, follows only the child jobs generated by that root job, waits for the whole lineage to reach terminal states, processes that lineage's result deliveries, returns the results, and then exits. It must not require the user to start the web UI, API server, or a persistent Worker first. A local MCP host starts the STDIO Server automatically; do not ask the user to start it separately when the MCP connection is already available.

The scoped Worker must not claim items or deliveries belonging to unrelated queued jobs. It starts only the minimum runtime needed for the requested collection; it does not start Cookie maintenance or the web UI. Starting this temporary Worker is part of fulfilling an explicit request to collect a supported dataset and does not need a separate confirmation.

Use MCP `crawler_create_job` or CLI `create` when the user explicitly asks to queue work for an already managed deployment, wants a durable task without waiting, or `crawler_doctor.mcp_runtime.synchronous_run_enabled=false`. In that queue-only mode, verify that an external `amazon-crawler serve` or `amazon-crawler worker` process consumes the same `CRAWLER_DB_PATH`; if no managed Worker is present, stop and name the exact startup command rather than claiming the job will run.

Always run MCP `crawler_doctor` or CLI `doctor` before creating or running a job. The CLI wrapper safely loads `CRAWLER_*` values from the project-root `.env` without executing the file as shell code; explicit process environment values take precedence. The MCP Server reads only its process environment, normally forwarded by the MCP host. If `configuration_ready` is false, stop and tell the user exactly which environment-variable names appear in `blocking_issues` and where to set them. Never ask the user to paste a Cookie, proxy URL, proxy password, Redis URL, or other secret into the Agent conversation or task arguments. The user must put those values in the project-root `.env`, MCP host environment, or a deployment-platform Secret, then invoke the doctor operation again. Direct CLI and directly launched MCP users must load `.env` into their shell.

The doctor operation is a secret-free structural check. It does not contact Amazon, Redis, or the proxy provider. Its persistent Worker status is deliberately `not_verified`, but that is not a blocker for `crawler_run_job` or `run` because the scoped runner owns a temporary Worker.

For queue-only creation, do not describe `created: true` as “the crawl has started.” It means the durable job was accepted; MCP also returns `completion_evidence=false`. For a scoped run, require `runner.started=true`, `runner.stopped_reason=terminal`, terminal states for every entry in `jobs`, and a terminal `lineage_status` before describing the execution as complete.

## Workflow

1. Select one interface: connected `crawler_*` MCP tools first, otherwise the project-local wrapper.
2. Run `crawler_doctor` or `doctor`. Stop on any `blocking_issues` and give the user the returned configuration instructions without requesting secret values in chat.
3. For a managed MCP deployment, run `crawler_health` before creating work. Stop when `accepting_jobs=false`; the public Tool intentionally does not expose internal MCP metrics, alerts, or audit data. Run `crawler_capabilities` or `capabilities` when the marketplace or input form is unclear.
4. Normalize the user's explicit scope into the selected task contract. Read [references/input-contracts.md](references/input-contracts.md) for non-product tasks.
5. Use `crawler_run_job` or `run` by default only when synchronous execution is enabled. Preserve its returned `job.id`. Keep the default `sqlite` result sink unless the user requests another sink shown by capabilities.
6. Report `lineage_status`, every job's terminal status, item counts, result row count, bounded failure reasons, and whether secondary deliveries completed. `completed=true` with `lineage_status=failed` is a completed execution but not a successful collection.
7. If the scoped run reaches its soft timeout or an operator-controlled state, report the durable job ID and current state. Do not create a duplicate as a workaround.
8. Use queue-only `crawler_create_job` or `create` only for an explicitly managed deployment, and confirm an external Worker is available before claiming that queued work will execute.
9. Use `crawler_pause_job` or `pause` for a safe stop. In-flight work may finish before status becomes `paused`.
10. Use `crawler_resume_job` or `resume` only for `paused` or `pause_requested` jobs.
11. Use `crawler_cancel_job` or `cancel` only after the user explicitly confirms cancellation. Local MCP uses `confirm=true`; production MCP requires an operator-issued `approval_receipt`. The Skill must never issue or fabricate that receipt.
12. Follow `page.next_cursor` for results, events, or deliveries only as far as needed for the user's answer. Keep raw large result sets outside the conversation and report bounded counts and evidence.

## Commands

When MCP is connected, use these tools instead of Shell commands:

```text
crawler_doctor
crawler_capabilities
crawler_health
crawler_run_job
crawler_create_job
crawler_list_jobs
crawler_get_job
crawler_get_results
crawler_get_events
crawler_get_deliveries
crawler_pause_job
crawler_resume_job
crawler_cancel_job
```

MCP `crawler_run_job` and `crawler_create_job` accept structured `inputs`, `kind`, `marketplace_id`, `postal_code`, `execution_mode`, `priority`, `max_attempts`, `idempotency_key`, `result_sinks`, `tags`, and `requested_fields`. `crawler_run_job` additionally accepts `timeout_seconds`. The schemas may expose `approval_receipt` for an already authorized production operation; it is not a substitute for user confirmation, and this Skill does not sign one. Never add secret fields; the schema intentionally excludes them.

If MCP is not connected, run the following commands from the project root:

`B0XXXXXXXX` below is only an ASIN-shaped marker. Replace it with the authorized target product's real 10-character ASIN. Replace `JOB_ID` with the `job.id` returned by `create`.

```bash
python skills/operate-amazon-crawler/scripts/crawler_cli.py doctor
python skills/operate-amazon-crawler/scripts/crawler_cli.py capabilities
python skills/operate-amazon-crawler/scripts/crawler_cli.py run B0XXXXXXXX --marketplace US --mode standard
```

## Result Shape

`results` returns one result envelope per completed job input, not necessarily one business row. Product fields are inside `results[].data`. Search tasks return one page envelope whose `data.row_count` is the number of collected rows, `data.items` contains those rows, and `data.task` preserves the normalized search request. Do not report a search as one row merely because the outer `results` array contains one envelope.

## Safety Rules

- Do not accept non-Amazon URLs, arbitrary request headers, cookies, proxies, credentials, or database paths from an Agent request.
- Accept only result sink names returned by `capabilities`; never accept a connection URL or filesystem path as a task option.
- Require explicit user confirmation before selecting any external MySQL or Redis result sink. For CLI, include `--confirm-external-result-write`; for MCP, stop unless a trusted operator has issued the exact one-time approval receipt. `sqlite` and `jsonl` do not need approval.
- Never call `amazon-crawler-mcp-approval`, read `CRAWLER_MCP_APPROVAL_SIGNING_KEY`, mint a Bearer Token, or weaken authentication, scope, rate, concurrency, output, or circuit-breaker settings through this Skill.
- Do not run Cookie production, Cookie maintenance, task import/export, or external state-sync commands; those operations are outside this skill and require deployment authority.
- Do not start the web/API server or a persistent global Worker through this skill. The job-scoped temporary Worker used by `crawler_run_job` or `run` is permitted and required.
- Do not claim that `pause` interrupts an in-flight HTTP request; it stops new claims and waits for current leases.
- Do not describe a crawl as failed merely because a secondary result delivery is retrying. Report crawl state and delivery state separately.
- Do not hide partial or failed items. Report error codes and attempts without exposing credentials or raw cookies.
- Do not change parser code, promote an evaluation candidate, or alter rate limits through this operator skill.
- Treat HTML evidence as potentially sensitive. Return hashes and bounded summaries unless the user explicitly requests the stored artifact.
